中文摘要

Designer Hub 把（如云筑家 App 导出的）装修方案变成链上创作资产：每份方案是一个 ERC-721，可 Remix、 链上谱系可追溯、创作者自主定价、被使用时即时分账（原创 90/10，衍生 85/10/5，无平台金库）。 主流程用 Passkey（WebAuthn/P-256）登录，私钥不出设备安全芯片，relayer 代付 gas 却无法篡改调用； 内容本体永不上链，只存承诺哈希。它交付的是可被第三方集成的原语（含类型化 SDK 与集成文档）， 正对应 Track 04 的 identity / provenance / data ownership / agent trust。

What it is

Four composable primitives

Deliberately not interior-design-specific: “a tamper-proof way to sign, attribute and pay for content that is generated and remixed over time” applies to any generative content.

Identity

Passkey smart account

P256PasskeyAccount + PasskeyAccountFactory. Mnemonic-free; address = CREATE2(x, y, rpIdHash, originHash). The private key never leaves the device secure element. A real WebAuthn assertion is verified on-chain, binding the exact calldata + nonce, so any relayer can pay gas without being able to alter the call.

Provenance / data ownership

Content attestation

ProvenanceRegistry stores only a commitment keccak256(contentHash ‖ salt) — the content itself never goes on-chain, yet provenance and a timestamp are provable. Privacy-preserving attribution.

Remixable assets with lineage

Scheme NFT + market

DreamScheme (ERC-721 + ERC-2981 5% royalty) records on-chain lineage (parentId, v1→v2→v3). SchemeMarket: creator sets the price; applying a scheme pays out instantly and directly — 90/10 original, 85/10/5 remixed. No vault, no withdraw().

Agent trust

AI agent registry

AgentRegistry registers AI generators + reputation; mint / remix carry the generating agentId on-chain, so a scheme and the model that made it are publicly attributable. Kimi is pre-registered as agentId = 1.

How it works

One scheme JSON in, one on-chain asset out

The 云筑家 app (a separate repo) only hands off a scheme JSON; this repo depends on none of its services.

01Passkey login → CREATE2 account
02Mint ERC-721 scheme
03Pin metadata to IPFS
04Remix (parentId on-chain)
05Apply → instant split
06Leaderboard: attention

For developers · Design & Craft (20%)

Build on it without our UI

Install the typed SDK and skip the cryptography. Three integration paths: read-only (no wallet), standard EOA, or a passkey account with optional gas sponsorship.

npm i @yunzhujia/sdk viem
import { publicClient, readTotalSupply, readScheme, readSplitPreview } from "@yunzhujia/sdk";

const client = publicClient();                       // Monad Testnet (10143)
const s = await readScheme(client, await readTotalSupply(client));
console.log(s.creator, s.parentId, s.remixCount, s.priceWei);
import { createPasskey, rpIdHashHex, originHashHex, passkeyFactoryAbi,
         buildAttestData, deriveSingleChallenge, signAssertion,
         publicClient, monadTestnet } from "@yunzhujia/sdk";

const cred = await createPasskey({ rpId: "yourdomain.xyz" });
const account = await publicClient().readContract({
  address: monadTestnet.passkeyAccountFactory, abi: passkeyFactoryAbi,
  functionName: "accountOf",
  args: [BigInt(cred.x), BigInt(cred.y),
         rpIdHashHex("yourdomain.xyz"), originHashHex("https://yourdomain.xyz")],
});

Originality & Track Insight (15%)

Why it isn’t capturable by a single platform

  • No platform vault. Payments go straight from buyer to creator/platform/ancestor in the same transaction — there is nothing to freeze and no operator-held balance.
  • Lineage is on-chain, not in a database. Attribution survives any single app.
  • The relayer is permissionless and replaceable. execute(...) can be called by anyone — the signature, not the sender, is the authorization.
  • Identity is the user’s. A passkey in the user’s secure element, not a custodial account.
  • Privacy-preserving. Content itself never touches the chain — only a commitment hash.

Rolling your own means re-implementing: WebAuthn assertion parsing + P-256 verification (EC2 COSE keys, DER→(r,s), low-s edge cases), a CREATE2 account with replay-safe nonces, an anti-tamper challenge scheme, an attestation registry, and a lineage-aware revenue splitter — about a week of security-sensitive work, compressed into a few typed calls.

Traction & Path Forward (20%)

Honest status + a concrete plan

No third-party integration yet. Traction today is self-served only (a first-party integrator — the 云筑家 app — already exports the scheme JSON). We state this plainly rather than overclaim.
  • Ship the kit (done): publish @yunzhujia/sdk + integration guide + runnable examples.
  • Land one integrator during the event: recruit one external team (a design tool, an asset library, or an AI-agent platform) to mint/attest through the SDK — even a read-only integration counts.
  • Post-event: open a small integration-bounty / “built on Designer Hub” track, add a builtWith registry, and host the app (demo URL + recorded video).
  • Follow-ups: metered/paid relayer, per-agent analytics on AgentRegistry, and an EIP draft for the commitment+lineage pattern.
